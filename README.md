# 비밀번호 보안 도구 (`26-w12-password`)

> **Zero-Knowledge 기반 비밀번호 강도 분석 및 k-익명성 유출 조회 도구**  
> 비밀번호 원문은 서버로 절대 전송되지 않으며, 오직 브라우저 내부 메모리에서만 안전하게 동작합니다.

---

## 소개

본 프로젝트는 사이버보안 원칙을 기반으로 기획된 **비밀번호 종합 점검 및 안전한 생성 대시보드**입니다.

- **섹션 1 [비밀번호 강도 & 유출 확인]**: 입력 즉시 브라우저 로컬에서 계산되는 실시간 4단계 강도 게이지(0~100점)와 세부 체크리스트를 제공하며, HIBP(Have I Been Pwned) API를 통한 k-익명성(k-Anonymity) 유출 조회를 지원합니다.
- **섹션 2 [안전한 비밀번호 생성기]**: `Math.random()`을 일체 배제하고 암호학적 난수(`window.crypto.getRandomValues()`)만을 사용하여 안전한 비밀번호를 생성하고, 원클릭으로 검사 창에 바로 전달하여 테스트할 수 있습니다.
- **테마 전환**: 사용자 눈의 피로를 덜고 접근성을 높이기 위해 다크 모드와 라이트 모드 전환을 완벽히 지원합니다.

   - 이전 실습에서는 이미 완성된 의존성과 설정 파일 위에서 기능 개발에만 집중했다면, 이번에는 빈 디렉터리에서 프레임워크(React)와 언어(JavaScript)를 직접 선택하고 프로젝트 뼈대를 올렸습니다.
   - 특히 배포 경로 호환을 위한 `vite.config.js`의 `base: './'` 설정, `package.json`의 `gh-pages` 배포 스크립트 등록, Linter(`oxlint`) 검증 등 빌드 도구와 패키지 매니저의 동작 원리를 온전히 이해할 수 있었습니다.

2. **`create-vite`가 README.md와 .gitignore를 덮어쓴 것을 보고 무엇을 느꼈나요? .gitignore에 무엇을 추가했고, 왜 필요한가요?**
   - 자동화 생성 도구는 동일 파일명이 있을 경우 경고 없이 덮어쓸 수 있으므로, 프로젝트 초기 구성 시 백업과 버전 관리(Git)의 중요성을 절감했습니다.
   - 기본 생성된 `.gitignore`에는 `.env.local`만 제외되어 있고 `.env` 파일 자체가 누락되어 있었습니다. API 키나 DB 인증 정보 등 민감한 환경변수가 GitHub 원격 저장소에 커밋되어 유출되는 대형 보안 사고를 방지하기 위해 다음 규칙을 추가했습니다:
     ```gitignore
     # 환경변수 — 절대 커밋하지 않습니다
     .env
     .env.*
     !.env.example
     ```

## 나의 AI 기획·구현 과정

1. **어떤 AI 협업 방식을 선택했나요?**
   - **Antigravity IDE Implementation Plan & Step-by-Step 구현 방식**을 선택했습니다.
   - 기획서의 핵심 요구사항(보안 원칙, 점수 산출 공식, k-익명성 절차, 단일 페이지 2개 섹션)을 먼저 확립한 뒤, AI와 단계별 구현 계획을 검토하고 유틸리티 모듈(`strengthUtils.js`, `cryptoUtils.js`) 분리 → UI 및 스타일(`App.jsx`, `App.css`) → 빌드/린트 검증 순으로 단계적으로 완성했습니다.

2. **비밀번호 "강도"의 기준을 어떻게 정했나요?**
   - **총 100점 만점 / 4단계 등급 (위험: 0~39점, 취약: 40~59점, 보통: 60~79점, 안전: 80~100점)**
     - **길이 점수 (최대 50점)**: 8자 이상(+20점), 12자 이상(+20점), 16자 이상(+10점)
     - **문자 다양성 (최대 40점)**: 소문자, 대문자, 숫자, 특수문자 각 포함 시 +10점
     - **복합 보너스 (+10점)**: 12자 이상이면서 4종류 문자를 모두 포함한 경우
     - **취약 패턴 감점**: 흔한 단어/순차 배열(`1234`, `qwer`, `asdf`, `password`, `admin` 등) 포함 시 `-30점`, 동일 문자 3회 연속 반복(`aaa`, `111`) 시 `-20점` (최저 0점 보장)

3. **구현 중 가장 막혔던 문제는 무엇이었고, 어떻게 해결했나요?**
   - HIBP API 응답의 해시 서픽스(suffix)는 모두 대문자(Uppercase)로 전달되므로, 클라이언트 측 SHA-1 해시를 소문자로 비교할 경우 유출된 비밀번호임에도 "안전"으로 잘못 판정되는 문제가 발생할 수 있었습니다.
   - 이를 방지하기 위해 `computeSha1Hex`에서 `.toUpperCase()`를 필수 적용하고, 응답 라인 파싱 시 `lineSuffix.trim().toUpperCase() === suffix`로 엄격하게 대소문자를 일치시켰습니다.
   - 또한 `Add-Padding: true` 헤더로 인해 응답에 포함되는 유출 횟수 0인 가짜 더미 항목을 `count === 0`으로 정확히 걸러내어 유출 판정의 신뢰도를 확보했습니다.

## 보안 점검 (사이버보안과 체크포인트)

1. **비밀번호 생성에 `Math.random()` 대신 `crypto.getRandomValues()`를 써야 하는 이유는 무엇인가요?**
   - `Math.random()`은 결정론적 알고리즘(예: XorShift128+)을 사용하는 **의사난수 생성기(PRNG)**입니다. 내부 시드값과 상태가 노출되면 다음에 생성될 값을 수학적으로 역추적·예측할 수 있어 공격자의 무차별 대입 공격에 취약합니다.
   - 반면 `window.crypto.getRandomValues()`는 운영체제 커널의 하드웨어 인터럽트, 소음 등 물리적 엔트로피 풀을 활용하는 **암호학적으로 안전한 의사난수 생성기(CSPRNG)**이므로 통계적·수학적으로 난수 예측이 불가능하여 비밀번호 및 암호키 생성에 필수적입니다.

2. **유출 확인 시 Network 탭에서 확인한 실제 요청 주소를 그대로 적어 주세요.**
   - 비밀번호 `password` 조회 시 전송된 실제 요청 주소:
     ```http
     GET https://api.pwnedpasswords.com/range/5BAA6
     ```
   - 비밀번호 `password`의 전체 SHA-1 해시는 `5BAA61E4C9B93F3F0682250B6CF8331B7EE68FD8`입니다.
   - **검증 결과**: 비밀번호 원문(`password`)이나 뒤 35자리 해시(`1E4C9B93F3F0682250B6CF8331B7EE68FD8`)는 네트워크 URL, 쿼리, 헤더, 바디 어디에도 전혀 전송되지 않았으며, 오직 앞 5글자(`5BAA6`)만 전송되었습니다.

3. **k-익명성 방식으로도 서버가 알 수 있는 정보는 무엇인가요? (완전한 익명이 아닌 이유)**
   - **조회 시점 및 IP 주소**: 서버는 요청이 들어온 정확한 일시와 사용자의 공인 IP 주소를 수집할 수 있습니다.
   - **해시 접두사(Prefix)**: 5글자 접두사가 일치하는 약 수백~수천 개의 비밀번호 풀(Bucket) 범위로 사용자의 비밀번호 후보군이 좁혀집니다.
   - **트래픽 상관관계**: 만약 특정 사용자가 여러 비밀번호를 연속으로 조회할 경우 동일 IP의 요청 패턴을 통해 추가적인 메타데이터 분석이 가능합니다. (따라서 비밀번호 원문은 보호되지만 "조회 행위 자체"를 완전히 은닉할 수는 없습니다.)

## 나만의 확장 기능

1. **`Add-Padding: true` 헤더 기반 트래픽 분석(Traffic Analysis) 방어**:
   - 서버 응답에 유출 횟수 0인 임의의 가짜 해시 레코드를 삽입하여 패킷 크기만으로 어떤 접두사인지 추측하지 못하도록 보호하고, 클라이언트에서 0회 항목을 자동 필터링했습니다.
2. **다크 모드 & 라이트 모드 듀얼 테마 지원**:
   - CSS 변수 기반 테마 시스템을 구축하여 시스템 설정(`prefers-color-scheme`)을 자동 감지하고, 원클릭으로 눈이 편안한 다크 모드와 선명한 라이트 모드를 전환할 수 있도록 구현했습니다.
3. **CSPRNG 모듈로 편향(Modulo Bias) 제거 거부 샘플링**:
   - 단순 `%` 연산으로 인한 특정 문자 쏠림 현상을 방지하기 위해 거부 샘플링(Rejection Sampling) 알고리즘을 적용하고, 선택된 각 문자셋에서 최소 1글자씩 먼저 보장한 뒤 피셔-예이츠 셔플로 배치했습니다.
4. **섹션 간 원클릭 비밀번호 전달 UX**:
   - 생성기에서 만든 비밀번호를 클립보드로 복사할 뿐만 아니라, `[위 입력창에 바로 넣기]` 버튼을 통해 섹션 1로 즉시 주입하고 스무스 스크롤과 포커스를 지원합니다.
